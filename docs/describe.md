# Linux 现代拼音输入法架构设计与技术选型文档（集成自绘现代 UI 版）

## 1. 核心架构演进：接管候选框 UI

常规 Fcitx5 插件直接将候选列表交给 Fcitx5 默认的 ClassicUI 模块绘制。为了拥有完全自主可控、现代化、高颜值的界面，我们采用 **“引擎截获 + 自绘前端”** 架构：

```
+--------------------------------------------------------------------------+
|                  Client Application (Chrome / Zed / Terminal)            |
+--------------------------------------------------------------------------+
                                    │ (按键输入 / 光标焦点变化)
+-----------------------------------▼--------------------------------------+
|                     Fcitx5 Core (Daemon / 协议中转层)                     |
|  - 负责捕获全局按键并路由到本插件                                        |
|  - 提取光标绝对屏幕坐标 (Cursor Rect) 并通知本插件                        |
+-----------------------------------┬--------------------------------------+
                                    │ C ABI (Fcitx5 Addon API)
+ - - - - - - - - - - - - - - - - - ▼ - - - - - - - - - - - - - - - - - - -+
:  Rust IME Plugin 宿主插件 (集成在 Fcitx5 进程内部)                       :
:                                                                          :
:  +--------------------------------------------------------------------+  :
:  | 1. Fcitx5 拦截层 (UI Suppressor & Event Router)                    |  :
:  |    - 显式关闭 Fcitx5 默认 CandidateWindow UI 渲染                  |  :
:  |    - 提取：Cursor Position (X, Y, H)、按键事件、Preedit 状态       |  :
:  +----------------------------------┬---------------------------------+  :
:                                     │                                    :
:  +----------------------------------▼---------------------------------+  :
:  | 2. 拼音解码管线 (Decoding Pipeline Engine)                         |  :
:  |    - DAG 切分 / FST 字典 / Viterbi 动态规划 / 用户频次学习         |  :
:  +----------------------------------┬---------------------------------+  :
:                                     │                                    :
:                                     │ 进程内通道 / 共享内存              :
:  +----------------------------------▼---------------------------------+  :
:  | 3. 自绘候选框渲染层 (Modern Renderer: Slint / Smithay)             |  :
:  |    - Wayland: Layer Shell / Subsurface / Wlr-Foreign-Toplevel      |  :
:  |    - X11: Composite Redirect Window (ARGB 32-bit 透明真彩色)       |  :
:  |    - 视觉特效：圆角平滑裁剪、动态物理阴影、模糊滤镜、动画过渡      |  :
```

## 2. 候选词界面关键技术选型 (GUI & Rendering)

在 Linux 上开发输入法浮窗，最大的技术壁垒是**无边框穿透、透明通道支持、Wayland 定位协议以及微秒级冷启动渲染**。

### 2.1 GUI 引擎选型对比

| 框架 | 渲染后端 | 内存开销 | 现代动效支持 | 最终评价 |
| --- | --- | --- | --- | --- |
| **Slint (推荐)** | `femtovg` / Skia / Vulkan | **极低** (~10-15MB) | 声明式 DSL，天然支持圆角、阴影、平滑过渡 | **首选**。纯 Rust 驱动，界面与逻辑彻底解耦，语法极简且极轻。 |
| **Iced** | WGPU / `softbuffer` | 中等 (~25MB) | 纯代码声明式，定制高度自由，但无现成样式语法 | **次选**。无 DSL，调整样式需频繁编译。 |
| **Tauri (Webview)** | WebKitGTK | **过大** (>150MB) | 极强 (CSS/HTML)，开发速度快 | **坚决淘汰**。打字首屏冷启动会有明显白屏与延迟，内存无法接受。 |
| **Qt 6 / QML** | QPainter / RHI | 大 (~40-60MB) | 强，成熟但臃肿，C++ 绑定啰嗦 | **不推荐**。与纯 Rust 技术栈冲突，依赖过多动态库。 |

**确定选型：Slint (使用 Rust API + 声明式 `.slint` 模板)**。

## 3. 跨显示协议的窗口定位与透明窗口实现

为了在 X11 和 Wayland 下均能精准把优雅的 UI 贴在光标正下方，需打通底层平台协议：

### 3.1 Wayland 窗口挂载 (Wayland Shell)

在 Wayland 下，普通应用无法随意在屏幕绝对坐标 `(X, Y)` 弹出窗口。必须根据桌面环境使用对应协议：

1. **wlr-layer-shell 协议**（Sway / Hyprland 等平铺桌面）：
* 通过 `wayland-client` 申请 `zwlr_layer_shell_v1` 图层。
* 设置 Layer 为 `Overlay`，利用 Anchor 与 Margin 将弹窗动态对齐到光标包围盒。


2. **KDE / GNOME 环境**：
* 利用 Fcitx5 暴露的 Wayland 内部连接或直接利用透明 Subsurface/Popup 机制，由 Fcitx5 的 Native Helper 协助更新几何坐标。



### 3.2 X11 窗口透明与阴影 (ARGB Composite)

* 在 X11 下，普通窗口直接变圆角会有黑色锯齿边缘。
* 方案：在创建 X11 窗口时，显式配置 `32-bit Visual (ARGB)`，结合 Composite 扩展，配合现代合成器（Picom / Mutter / KWin）实现像素级真透明高斯模糊与扩散阴影。

## 4. 优雅候选框的交互设计规范 (UI/UX Design)

为了对标 macOS 和搜狗/百度的细腻手感，界面层需严格遵循以下规范：

```
+--------------------------------------------------------------+
|  pinyin: ni'hao'a [你好啊]                       ⚙  ☁  CN     | <- Header: 拼音高亮+切分线+状态
|--------------------------------------------------------------|
|  1. 你好啊                                                    | <- 首选项：主强调色高亮背景
|  2. 拟好    3. 泥蒿    4. 你好阿    5. 倪豪                   | <- 候选网格：排版呼吸感+快捷键数字
+--------------------------------------------------------------+
      ▼ 光标指示小箭头 (可选跟随)

```

1. **视觉层次 (Visual Polish)**：
* **背景**：深浅自适应配色，支持半透明磨砂亚克力玻璃（Acrylic Blur，85% 透明度）。
* **圆角与边框**：全边缘 `12px` 圆角，搭配 `1px` 微弱高亮描边（Stroke），增强暗黑模式下的立体边缘感知。
* **阴影**：多层混合 Box Shadow（内层硬阴影防虚化，外层大半径软阴影营造悬浮感）。


2. **动态过渡与高刷新率渲染**：
* **选词光标过渡**：使用 Spring（弹性动画）插值算子，当使用左右键/Tab 切换高亮词时，选词框背景平滑“滑动”到新位置，消除生硬的跳跃感。
* **按键即刻绘制**：Slint 的 Event Loop 与按键事件通过本地队列直连，单次重绘耗时严格控制在 **$1.5\text{ ms}$ 以内**（支持 144Hz/240Hz 电竞屏打字无残影）。

## 5. 核心状态机与 UI 的联动流水线

Fcitx5 插件捕获到输入时，数据流动如下：

```
用户击键 (Key Event) ──► Fcitx5 接口
                           │
                           ▼
                  [ime-core] 状态机
                     ├── 1. 检索 FST 词库与 N-gram 动态规划
                     ├── 2. 生成候选列表 (Vec<Candidate>) 与 Preedit 串
                     └── 3. 判定窗口可见性 (Has Candidates ? Visible : Hide)
                           │
                           ▼ 更新共享状态 (Slint ViewModel)
                  [ime-ui-slint] 渲染线程
                     ├── 1. 获取光标物理坐标: (x, y, cursor_height)
                     ├── 2. 计算智能避让边界 (屏幕底部不足时自动向上翻转)
                     ├── 3. 执行 Slint 差异更新并触发无撕裂重绘
                     └── 4. 监听鼠标悬停/点击交互（支持鼠标选词）

```

## 6. 模块架构与工程目录调整

将 UI 作为一个独立的轻量 Crate 引入，保持核心引擎的彻底纯粹性：

```text
fcitx5-rust-pinyin/
├── Cargo.toml
├── crates/
│   ├── ime-core/              # [纯 Rust] 解码器、拼音切分、Viterbi、语言模型
│   ├── ime-dict/              # [纯 Rust] FST 词库、redb 用户个性化数据库
│   ├── ime-ui/                # [Rust + Slint] 候选框渲染引擎 (NEW!)
│   │   ├── ui/
│   │   │   ├── candidate.slint # 声明式 UI 样式、布局、动效定义
│   │   │   └── theme.slint     # 配色方案、暗黑模式切换
│   │   ├── src/
│   │   │   ├── window.rs       # 窗口生命周期与平台 (Wayland/X11) 适配
│   │   │   └── adapter.rs      # 候选数据转 UI 绑定的桥接层
│   │   └── Cargo.toml
│   └── fcitx5-sys/            # C++ 胶水层：屏蔽 Fcitx5 自带 UI，回传坐标与按键

```

通过这种架构，你既不用去淌 Linux 桌面从零截获键盘、适配每个应用程序光标位置的浑水（由 Fcitx5 代劳），又彻底摆脱了 Fcitx5 默认老旧候选框样式的束缚，打磨出兼具极致性能与高颜值质感的桌面拼音输入体验。
