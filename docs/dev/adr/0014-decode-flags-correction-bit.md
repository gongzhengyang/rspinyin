# ADR-0014：`DecodeFlags::CORRECTION` 位（拼写纠错）

## 状态

已接受。

## 背景

拼写纠错（`docs/dev/features-add-phase3.md` 的 `TASK-3.01.01`）需要一个新的解码开关：开启后，DAG 对**全码精确查询 miss** 的输入展开纠错变体边（键盘邻位替换与邻键颠倒，每音节至多一步）。`DecodeFlags` 是冻结契约（ADR-0001），`AGENTS.md` §8.22 要求改动走 ADR。

位域的前向兼容性已由 `decode.rs` 模块注释论证：新读者通过 `from_bits_truncate` 丢弃未知位，旧读者忽略新位，无需版本号。ADR-0005（`SHUANGPIN`/`PHRASE`/`SCRIPT` 追加）有先例。

## 决策

1. `DecodeFlags` 追加 `CORRECTION = 1 << 14`。位域命名空间从 `0x3FFF` 扩到 `0x7FFF`；`decode.rs` 中钉住 `all().bits()` 的测试随行更新，这是「追加位是深思熟虑之举」的既有守卫（ADR-0005 先例）。
2. 该位自兼主开关：不像模糊音那样区分主开关与类别位。默认关；配置面为 `[engine] correction = false`（`ime-config`，非冻结契约）。
3. 语义冻结：**纠错边只在精确 miss 分支展开**——精确 + 模糊扩边已可完整切分的输入零纠错成本、零候选扰动；这是「纠错永不进入已拼对输入的最优路径」的结构性保证，测试钉死。

## 实现注记（ime-core 内部，非契约）

落地时对任务卡草图的三处修正，均不触碰冻结契约：

- **罚值符号域**：卡面草写的 `-998` 是对数域的书写习惯（−log 0.01 ≈ 3.9）。本工作区罚值约定为**正整数、由 sweep 以 `saturating_sub` 减入 Q16.16 分数**（模糊音 `12 << 8`、简拼 `6 << 8` 同例），故落地为 `998 << 8`（≈3.898 个对数单位，约为模糊音罚的 80 倍），并以编译期断言钉住 `CORRECTION_PENALTY_Q8 > FUZZY_PENALTY_Q8` 的分档序。若按字面 `-998` 直接减入分数，纠错反而比模糊音轻，违背卡片自己声明的「重罚防污染」意图。
- **`corrections_of` 返回音节表标识**：卡面草写返回 `SmallVec<[String; 4]>`；落地返回 `SmallVec<[SyllableId; 4]>`（栈上缓冲 + 查表过滤同步完成），纠错扩边路径零分配，与 `fuzzy::variants` 同形。
- **双拼键域**：卡面边缘条件「纠错作用于双拼键」按「纠错作用于 DAG 所见文本」落地——双拼键在进 DAG 前已重写为全拼（状态机 `rewrite_input`），纠错表作用其上；键域纠错（对原始双拼键做邻位表）留待后续需要时另立登记。

## 后果

旧构建读到新位静默忽略，读写双方无需同步升级。纠错候选经 `Candidate.annotation`（既有 wire 字段，无变更）标注原拼写，错音提示卡（`TASK-3.05.02`）为消费方。
