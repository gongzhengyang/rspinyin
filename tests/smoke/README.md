# tests/smoke — 解码冒烟基线

数据驱动的解码回归资产：一行一个用例，「这批键必须出这批字」。
运行方式（在仓库根目录）：

```bash
cargo xtask testd-smoke
```

- 全绿输出一行汇总；任何一行偏离基线即输出 `FAIL case_id keys=… expected=… got=…` 并以非零退出码结束（门禁红）。
- `--verbose` 保留为调试开关；定位单行行为时改用 `xtask testd-engine` + 场景文件看整页候选。
- 200 例全跑约 1–2 秒（纯内存重放，仅挂载一次 `data/compiled/base.dict`）。

## 用例格式

TAB 分隔，`#` 行与空行跳过；每行至少三列，第四列起为（空格分隔的）标签：

```text
case_id  key_sequence  expected_text  [tags...]
```

- `key_sequence`：小写拼音原键，`'` 强制音节边界；`ü` 与 `v` 两种 ü 拼写都合法（引擎归一化折叠）。
- `expected_text` 四种形态：
  - 字面文本 与 `@first:<文本>` —— 首选候选（即空格键将上屏的第一条）必须逐字等于该文本。两种写法同一断言，字面形式让文件读起来像句子。
  - `@contains:<文本>` —— 首页（9 条）候选中有候选**包含**该文本（子串）。用于切分歧义：不要求第一选择让位，只要求另一读法可达。
  - `@regex:<模式>` —— 首选候选匹配正则。留给可变文本（组合日期、中英混排等后续卡）。
- 非法输入（列数不足、重复 case_id、非拼音键、拼错的 `@` 前缀）整集拒绝并指明行号；空用例集按错误处理——零条基线等于没钉住任何行为。

## 分带

| 标签 | 来源 | 维护方式 |
|---|---|---|
| `core` | 从留出集 `crates/ime-core/tests/fixtures/lm_holdout.tsv` 派生：引擎当前已答对的行，按留出集顺序取前 170 条 | **再生成而非手改**：`cargo xtask testd-smoke --derive-from-holdout crates/ime-core/tests/fixtures/lm_holdout.tsv` |
| `ambiguity` | 手写：切分歧义（xi'an/xian、fangan、ü 拼写等） | 手工维护 |
| `edge` | 手写：边界行为（强制边界、无切分直通、单韵母等） | 手工维护 |

再生成只重写 `core` 带，其余带原样保留。

## 什么时候会变红，怎么办

- **排名回归**（词库、打分、切分的改动弄丢了一条已正确的行为）→ 修排名，不许改期望。
- **有意的行为变更**（例如某次合并让某词升到首选）→ 先让全量门禁跑出事实，再手工把该行改成新期望并在提交信息里说明依据；禁止顺手大批量改写。
- **词典重建后批量变红** → 先看 `xtask tune` 的 top1 曲线确认是整体升降还是个别行漂移，再决定是修复还是重派生 `core` 带。

## 边界

本通道只对**解码契约**负责：挂载的词典 + 从未记录过的用户词库 + 出厂配置。
关于宿主、输入法切换、窗口几何的断言属于 `xtask testd`（XTEST）通道，两者结果不得互相引用。
